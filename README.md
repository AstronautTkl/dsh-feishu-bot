让 DSH 的**审批**和**进度**出现在飞书里：任务跑完会通知你，需要授权时手机上点一下就能批，不用一直守着电脑。

> 适合经常让 DSH 跑长任务、又不总坐在电脑前的人。
> 走飞书长连接，**不需要公网地址、不需要内网穿透**。

---

## 它能做什么

| 场景 | 你会看到 |
|---|---|
| 工具需要授权 | 飞书弹出卡片：`同意 / 拒绝 / 看上下文 / 交给电脑` |
| 长任务跑完 | 飞书收到「本轮结束」和最近几条对话 |
| 中途报错 | 飞书收到错误摘要 |
| 想了解进度 | 发「列表」「看 3f2a」，直接看会话和消息 |

电脑端不受影响：选「两端同时」时，电脑还是照常弹确认框，两边谁先处理谁生效。

## 五分钟上手

### 第 1 步：在飞书建一个机器人（约 3 分钟）

1. 打开 <https://open.feishu.cn/app>，用团队管理员账号登录
2. **创建应用 → 企业自建应用**，名字随便填（比如 `DSH`）
3. **添加应用能力 → 机器人**
4. **权限管理**，开通这五项：

   | 权限名 | 用途 |
   |---|---|
   | 获取与发送单聊、群组消息 | 基础 |
   | 以应用的身份发消息 | 发卡片 |
   | 读取用户发给机器人的单聊消息 | 收你的指令 |
   | 获取群组中@机器人的消息（用群时） | 群里 @ 它 |
   | 获取群组信息 | 定位会话 |

5. **事件与回调**
   - 事件配置 → 订阅方式选 **长连接** → 添加事件「接收消息」`im.message.receive_v1`
   - 回调配置 → 同样选 **长连接** → 添加回调「卡片回传交互」`card.action.trigger`

6. **创建版本 → 申请发布 → 管理员审核通过**

   > 这一步最容易漏。不发布，事件订阅不生效，表现就是"插件显示已连接，但发消息没反应"。

7. **凭证与基础信息** 里复制 **App ID** 和 **App Secret**

### 第 2 步：装到 DSH

```bash
git clone https://github.com/<you>/dsh-feishu-bot.git
cd dsh-feishu-bot
npm install --omit=dev
```

然后在 DSH 里安装这个插件，`target` 填上面目录的**绝对路径**：

```
plugin_manager(action: "install_bundle", target: "/绝对路径/dsh-feishu-bot")
```

### 第 3 步：在设置里填配置

打开 **设置 → 飞书机器人**，粘贴 App ID 和 App Secret，点保存。

状态变成 **「一切就绪」** 就说明连上了。这里还能顺手把「审批怎么处理」选好。

### 第 4 步：在飞书里说句话完成绑定

找到这个机器人，**单聊**发一句 `帮助`。

第一次会要求绑定码：打开 `~/.dsh-feishu/bridge.log`，找到最后一条 `bind.code`，把那 6 位数字发成 `绑定 123456`。之后只认你一个人。

### 第 5 步：验证

- 设置页点 **「发送测试消息」** → 飞书应立刻收到一条
- 飞书发 **「测试审批」** → 弹一张卡片，点「同意」应显示 ✅

两步都通，就可以正常用了。

## 日常怎么用

### 指令

| 指令 | 作用 |
|---|---|
| `列表` | 当前打开的会话和运行状态 |
| `看 <会话号> [条数]` | 看最近消息，默认 14 条 |
| `待办` | 挂起中的审批和剩余时间 |
| `同意 / 拒绝 / 转电脑 <码>` | 处理审批（也可以直接点卡片按钮） |
| `远程 开\|关` | 远程审批总开关 |
| `范围 全部\|只读` | 哪些操作可以在手机批 |
| `双端 开\|关` | 电脑和手机是否同时等 |
| `通知 开\|关` | 完成 / 报错提醒 |
| `测试审批` | 发一张测试卡片 |
| `状态` | 连接状态、待审批数、绑定身份 |

### 审批卡片的四个按钮

- **同意** — 放行这一次操作（一次性授权，不会"记住"）
- **拒绝** — 拒绝这次调用
- **看上下文** — 把该会话最近 5 条消息发给你，看完再决定
- **交给电脑** — 把这次审批交回 DSH 界面

### 三种审批方式

| 方式 | 飞书 | 电脑 | 适合 |
|---|---|---|---|
| **两端同时**（默认） | 弹卡片 | 弹确认框 | 大多数情况，谁先点谁生效 |
| **只在手机** | 弹卡片 | 不弹 | 离开工位，全部在手机处理 |
| **只在电脑** | 只发通知 | 弹确认框 | 不希望审批经过飞书 |

「两端同时」会先给手机 2.5 秒的抢答窗口：手机上处理掉就不弹电脑框；没处理才弹。窗口可在高级设置里调。

## 常见问题

**飞书完全收不到消息？**
先看设置页状态是不是「已连接」。不是的话，最常见是开放平台没选「长连接」，或者应用版本没发布。

**有卡片，但点按钮没反应？**
去看 `~/.dsh-feishu/bridge.log` 有没有 `card.action` 记录。没有说明回调没到，回开放平台检查「卡片回传交互」这个回调是否加了、是否已发布。

**状态显示「飞书连接断开」？**
日志里搜 `ws.state`。`reconnecting` 会自动重连；`failed` 一般是 App ID / Secret 不对，或者应用被停用。

**电脑弹框和手机卡片同时出现，点哪个？**
都行，谁先点谁生效。电脑先点，卡片会同步成一样的结果；手机先点，电脑那个框直接关掉即可。

**会被通知刷屏吗？**
不会。只有跑超过 45 秒的轮次结束才推一次，报错才推一次。嫌多可以 `通知 关`。

## 安全须知

- 只有绑定过的飞书账号能用，其他人发的消息会被忽略
- 首次绑定需要本机日志里的 6 位码，防止别人先搭话绑上
- 审批是一次性授权，不做"以后都允许"
- 超时默认交回电脑，不会默认放行
- App Secret 只写不读：设置页只显示"已保存"
- 想更保守：把「审批范围」改成**只读操作**，写文件和执行命令仍需在电脑确认

**把审批搬到手机，等于把授权通道放到手机上。** 请只在自己的设备上绑定，不用时发 `远程 关`。

## 卸载

1. 在 DSH 里移除插件：`plugin_manager(action: "remove_bundle", target: "dsh-feishu-bot")`
2. 删掉本机数据（可选）：`~/.dsh-feishu/`

## 开发

```
index.js         入口：连接、命令分发、审批协调、事件监听
client.js        设置页（注册到 DSH 设置侧边栏）
src/format.js    纯格式化函数
src/state.js     本地状态 / 日志 / settings.local.json
src/cards.js     飞书卡片构造
src/configpage.js 设置页的 HTTP 接口
test/            单元测试
```

```bash
node --test     # 不依赖飞书 SDK 和网络
```

三条踩过的坑，改代码前值得先读：

1. `approval/request` 这类带作用域的事件必须注册在 **`ctx.root`** 上，插件自己的上下文收不到
2. 必须 **`prepend`**，否则电脑端 answerer 先决定、不调 `next()`，后面的监听器轮不到
3. 飞书事件回调 **3 秒内必须返回**，任何等待都要脱离回调，否则会被重投、命令执行两次
